# Развёртывание на Amvera

Причина переезда с PythonAnywhere — сайт недоступен из России, а заказчики
оттуда. Amvera — российский облачный хостинг, работает изнутри России без
проблем.

**Честно:** документация Amvera заметно скромнее, чем у PythonAnywhere —
часть шагов ниже (перенос реальной базы данных, создание админа) я не смог
до конца проверить по документации и разберём по факту, когда окажемся в
их панели — так же, как разбирались с WSGI-файлом на PythonAnywhere.

## Что уже готово в коде

- `amvera.yaml` — конфиг сборки/запуска.
- `requirements.txt` — добавлен `gunicorn` (боевой сервер, нужен на Amvera).
- `kiwiweb/settings.py` — путь к базе теперь настраивается переменной
  `DJANGO_DB_PATH` (на Amvera — `/data/db.sqlite3`, в постоянном хранилище;
  без неё всё работает как раньше, локально ничего не меняется).

## 1. Аккаунт и репозиторий

1. Зарегистрируйтесь на amvera.ru.
2. В панели — **Создать проект** → выберите подключение по Git → укажите
   тот же репозиторий, что и для PythonAnywhere:
   `https://github.com/gorokhovavaleriia/finplanersgo` (если приватный —
   Amvera попросит доступ, следуйте её инструкции по подключению GitHub).

Дальше Amvera должна сама увидеть `amvera.yaml` в корне репозитория и
предложить деплой по нему.

## 2. Переменные окружения

В настройках проекта (раздел **Переменные** / Environment variables)
добавьте:

```
DJANGO_SECRET_KEY = <тот же или новый, python3 -c "import secrets; print(secrets.token_urlsafe(50))">
DJANGO_DEBUG = False
DJANGO_ALLOWED_HOSTS = <домен, который выдаст Amvera, плюс www.finplanersgo.com когда подключите>
DJANGO_CSRF_TRUSTED_ORIGINS = https://<тот же домен>
FINTABLO_API_TOKEN = <токен из finance/data/secret.rtf>
DJANGO_DB_PATH = /data/db.sqlite3
```

## 3. Первый деплой и перенос данных — доразберём вместе

После первого успешного деплоя `/data/db.sqlite3` будет создан пустым
(только структура таблиц, без данных). Дальше два варианта, в зависимости
от того, что реально даёт Amvera (проверим по факту в их интерфейсе —
консоль, файловый менеджер или CLI):

- **Если есть доступ к консоли/файлам** — просто загрузите туда свой
  реальный `db.sqlite3` с Мака (`/Users/alexander/Desktop/kiwi-web/db.sqlite3`),
  как делали на PythonAnywhere. Так сохранятся и план, и перемещения
  между фондами, и учётка admin.
- **Если такого доступа нет** — придётся восстанавливать по частям: сами
  операции можно подтянуть заново из Финтабло (`python manage.py
  sync_fintablo`, если получится выполнить эту команду на сервере), а вот
  введённый план и перемещения между фондами так не восстановятся — их
  придётся ввести заново, либо всё-таки найти способ перенести файл.

Когда дойдём до этого шага — пришлите скриншот панели Amvera после
первого деплоя, разберёмся, что там доступно.

## 4. Синхронизация с Финтабло по расписанию

В документации Amvera есть отдельный сервис **Cron Jobs** (оплата по
времени выполнения). Команда для задачи:
```
python manage.py sync_fintablo
```
Периодичность — на ваше усмотрение, как и на PythonAnywhere.

## 5. Финальная проверка

- [ ] Сайт открывается по адресу, который выдала Amvera.
- [ ] Логин работает, данные (план, фонды) на месте.
- [ ] Cron-задача синхронизации отработала хотя бы раз.
- [ ] Сайт открывается из России (попросите кого-то из заказчиков
  проверить, или через российский VPN/прокси).
